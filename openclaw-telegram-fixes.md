# OpenClaw Telegram Notification Fixes

## Issues Identified

1. **Message Truncation** - Telegram messages from agents getting cut off
2. **Verbose Review Notifications** - Receiving noisy metadata instead of clean output
3. **Deprecation Warning** - Legacy `streamMode` config deprecated since v2026.2.21

---

## Fix 1: Message Truncation

The default `textChunkLimit` is 4000 characters. Messages exceeding this get split
and can appear truncated, especially announce messages from sub-agents.

**Edit `~/.openclaw/openclaw.json` on your VPS:**

```json5
{
  channels: {
    telegram: {
      // Increase chunk limit (Telegram max is 4096)
      textChunkLimit: 4096,

      // Split on paragraph boundaries instead of mid-sentence
      chunkMode: "newline"
    }
  }
}
```

## Fix 2: Verbose Review Notifications

The messages like:
```
📋 Task submitted FOR REVIEW by pango (google/gemini-3.1-pro-preview):
Review task "Scheduled Health Check: ..."
✅ output looks substantive
Reason: Output contains work artifacts...
Summary: I've verified and APPROVED Charles's...
```

This comes from your agent system prompts - specifically pango's review/approval
workflow. The "output looks substantive" check and verbose metadata are being
generated by pango and then announced back to Telegram.

### Option A: Update Pango's System Prompt (Recommended)

In your agent config for pango (`~/.openclaw/agents/pango/` or in `openclaw.json`
under `agents.pango`), modify the system prompt to produce concise Telegram output:

```json5
{
  agents: {
    pango: {
      // Add to existing system prompt:
      systemPrompt: "... [your existing prompt] ...\n\nIMPORTANT: When reviewing tasks and announcing results, keep your output concise for Telegram delivery. DO NOT include verbose metadata like 'output looks substantive' or 'Reason: ...' checks. Format review results as:\n- For approvals: '✅ Approved: [one-line summary of what was reviewed]'\n- For rejections: '❌ Rejected: [one-line reason]'\n- Do NOT echo back the full task description or scheduling metadata.\n- Only include the actual work output or a brief summary of findings."
    }
  }
}
```

### Option B: Suppress Sub-Agent Announces to Telegram

If you want to stop announce messages from sub-agents entirely on Telegram
(note: this is not fully supported yet per GitHub issue #13911, but there's a
workaround):

Add to your agent system prompts:
```
When completing a review task via sessions_send, reply with ANNOUNCE_SKIP
if the output is a simple approval. Only announce if there are critical
findings that need user attention.
```

### Option C: Use Heartbeat-Style Digest Instead

Instead of real-time announces, configure a digest:
```json5
{
  agents: {
    pango: {
      heartbeat: {
        target: "telegram",
        every: "1h",
        showOk: false,      // Suppress "all good" heartbeats
        showAlerts: true     // Only notify on problems
      }
    }
  }
}
```

## Fix 3: Deprecation Warning (streamMode)

Since OpenClaw v2026.2.21, the legacy `streamMode` config was deprecated.

**Replace this:**
```json5
{
  channels: {
    telegram: {
      streamMode: "partial"  // DEPRECATED
    }
  }
}
```

**With this:**
```json5
{
  channels: {
    telegram: {
      streaming: "partial"   // New format (or use boolean: true/false)
    }
  }
}
```

## Fix 4: Clean Up Charles Health Check Output

For Charles's scheduled health checks, update the cron job or system prompt to
produce cleaner output:

```json5
{
  agents: {
    charles: {
      systemPrompt: "... [your existing prompt] ...\n\nWhen running scheduled health checks:\n- Output ONLY the health check results (status, metrics, issues found)\n- Do NOT include task scheduling metadata\n- Keep output under 2000 characters for clean Telegram delivery\n- If system is healthy: '✅ Health Check OK - [date] - All systems nominal'\n- If degraded: '⚠️ Health Check DEGRADED - [specific issue]'"
    }
  }
}
```

```bash
# SSH into your VPS and edit the config:
nano ~/.openclaw/openclaw.json

# After making changes, restart the gateway:
openclaw gateway restart
```

